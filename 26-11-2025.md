## 🔐 Variables de Entorno vs URLs Hardcodeadas {#variables-de-entorno}

### ❌ **Problema**: URLs Hardcodeadas en el Código

```javascript
// MAL - URL hardcodeada
const apiUrl = "https://mi-api.azurewebsites.net/api/users";
const dbConnection =
  "Server=myserver;Database=mydb;User=admin;Password=123456;";
```

### ✅ **Solución**: Variables de Entorno

```javascript
// BIEN - Usando variables de entorno
const apiUrl = process.env.API_URL;
const dbConnection = process.env.DATABASE_CONNECTION;
const kafkaUrl = process.env.KAFKA_URL;
const rabbitMqUser = process.env.RABBITMQ_USER;
const rabbitMqPassword = process.env.RABBITMQ_PASSWORD;
```

### **¿Por qué usar Variables de Entorno?**

- **Seguridad**: No expones credenciales en el código
- **Flexibilidad**: Mismo código para diferentes entornos (dev, test, prod)
- **Mantenimiento**: Cambios sin recompilación
- **Información Sensible**: Usuarios, contraseñas, URLs de servicios

## 🏷️ Tags en Azure - Gestión de Recursos {#tags-azure}

### **¿Para qué se usan los Tags?**

Los tags son etiquetas para **agrupar y gestionar recursos** en Azure.

### **Ejemplo Práctico:**

```bash
# Crear App Services con tags
az webapp create --name "app1" --tags "Environment=Demo" "Project=ClienteDemo" "Schedule=AutoStop"
az webapp create --name "app2" --tags "Environment=Demo" "Project=ClienteDemo" "Schedule=AutoStop"
az webapp create --name "app3" --tags "Environment=Demo" "Project=ClienteDemo" "Schedule=AutoStop"
```

### **Casos de Uso:**

- **Automatización**: Apagar 6 apps a las 6 PM, encender a las 5 AM
- **Gestión por lotes**: Eliminar todos los recursos de demo con un comando
- **Facturación**: Agrupar costos por proyecto
- **Organización**: Separar por ambiente (dev, test, prod)

### **Comando para eliminar por tag:**

```bash
# Eliminar todos los recursos con tag "Environment=Demo"
az resource list --tag "Environment=Demo" --query "[].id" -o tsv | xargs -n1 az resource delete --ids
```

## 🔑 Azure Key Vault - Información Sensible {#azure-key-vault}

### **¿Qué es información sensible?**

- Cadenas de conexión de bases de datos
- URLs de servicios internos
- Credenciales de APIs
- Certificados
- Tokens de acceso

### **❌ Sin Seguridad - Visible:**

```javascript
// PELIGROSO - Información visible
const connectionString =
  "Server=prod-db.com;User=admin;Password=supersecret123;";
```

### **✅ Con Key Vault - Oculto:**

```javascript
// SEGURO - Referencia al Key Vault
const connectionString = process.env.DB_CONNECTION_FROM_KEYVAULT;
```

### **Configuración en Azure:**

```bash
# Crear Key Vault
az keyvault create --name "mi-keyvault" --resource-group "mi-rg"

# Agregar secreto
az keyvault secret set --vault-name "mi-keyvault" --name "DatabaseConnection" --value "Server=...;Password=..."

# Obtener URL del secreto
az keyvault secret show --vault-name "mi-keyvault" --name "DatabaseConnection" --query "id"
```

## 📦 Container Apps vs App Services {#container-apps-vs-app-services}

### **Similitudes:**

- Ambos ejecutan aplicaciones web
- Soporte para contenedores
- Variables de entorno
- Integración con Key Vault

### **Diferencias Clave:**

| Característica    | App Service                    | Container Apps                  |
| ----------------- | ------------------------------ | ------------------------------- |
| **Escalado**      | Automático y Manual            | Manual (configuración avanzada) |
| **Uso Principal** | Aplicaciones web tradicionales | Serverless/Functions            |
| **Complejidad**   | Más simple                     | Más configuración               |
| **Ingress**       | HTTP/HTTPS                     | TCP, HTTP, HTTPS                |

### **Ingress en Container Apps:**

- **HTTP/HTTPS**: Para APIs web
- **TCP**: Para servicios como Kafka, RabbitMQ
- **Interno**: Solo comunicación entre servicios

## 🔄 Kafka y RabbitMQ en Azure {#kafka-rabbitmq}

### **¿Dónde ejecutar Kafka y RabbitMQ?**

#### **Kafka:**

- **Puerto**: 9092 (TCP)
- **Protocolo**: TCP
- **Recomendación**: **Container Apps** (soporta TCP)

#### **RabbitMQ:**

- **Puerto**: 5672 (AMQP), 15672 (Management UI)
- **Protocolo**: TCP + HTTP
- **Recomendación**: **Container Apps** para el broker, **App Service** para Management UI

#### **Provectus (Kafka UI):**

- **Puerto**: 8080 (HTTP)
- **Protocolo**: HTTP
- **Recomendación**: **App Service** o **Container Apps**

### **Comando Docker para RabbitMQ:**

```bash
# ❌ MAL - Credenciales hardcodeadas
docker run -d -p 5672:5672 -p 15672:15672 -e RABBITMQ_DEFAULT_USER=myuser -e RABBITMQ_DEFAULT_PASS=mypassword rabbitmq:3-management

# ✅ BIEN - Usando variables de entorno del sistema
docker run -d -p 5672:5672 -p 15672:15672 -e RABBITMQ_DEFAULT_USER=$env:RABBIT_USER -e RABBITMQ_DEFAULT_PASS=$env:RABBIT_PASS rabbitmq:3-management
```

### **Variables de Entorno en Windows:**

```powershell
# Configurar variables de entorno
$env:RABBIT_USER = "admin"
$env:RABBIT_PASS = "admin123"

# Verificar
echo $env:RABBIT_USER
```

## ⚡ Serverless y Azure Functions {#serverless-functions}

### **¿Qué es Serverless?**

- **Sin gestión de servidores**: No te preocupas por la infraestructura
- **Escalado automático**: Se ajusta según la demanda
- **Pago por uso**: Solo pagas cuando se ejecuta
- **Eventos**: Se activa por triggers (HTTP, timer, queue, etc.)

### **¿Qué es una Azure Function?**

- Pequeñas piezas de código que se ejecutan en respuesta a eventos
- Similar a AWS Lambda
- Perfecta para microservicios pequeños y específicos

### **Ejemplo de uso:**

```javascript
// Azure Function que se activa con HTTP
module.exports = async function (context, req) {
  const name = req.query.name || "World";
  context.res = {
    body: `Hello, ${name}!`,
  };
};
```

## ☸️ Azure Kubernetes Service (AKS) {#azure-kubernetes}

### **¿Qué es Kubernetes?**

Plataforma para **ejecución, despliegue, escalado y administración** de contenedores.

### **Analogía:**

- **Docker**: Como cuidar un perrito (fácil)
- **Kubernetes**: Como manejar ganado (complejo pero potente)

### **Componentes de Kubernetes:**

#### **Cluster** 🏢

- **Definición**: Grupo completo de nodos
- **Analogía**: El edificio completo

#### **Nodos** 🖥️

- **Definición**: Máquinas virtuales o físicas
- **Analogía**: Pisos del edificio
- **Cantidad**: Puedes tener múltiples nodos

#### **Pods** 📦

- **Definición**: Unidad más pequeña, contiene uno o más contenedores
- **Analogía**: Oficinas en cada piso
- **Característica**: **Desechables** - pueden crearse y destruirse

### **Estructura Jerárquica:**

```
Cluster (Todo)
├── Nodo 1 (VM)
│   ├── Pod A (Contenedor Web)
│   └── Pod B (Contenedor API)
├── Nodo 2 (VM)
│   ├── Pod C (Contenedor DB)
│   └── Pod D (Contenedor Cache)
└── Nodo 3 (VM)
    └── Pod E (Contenedor Worker)
```

### **¿Por qué Kubernetes?**

- **Escalabilidad**: Miles de contenedores
- **Alta disponibilidad**: Si un nodo falla, otros continúan
- **Orquestación**: Gestión automática de contenedores
- **Ejemplo real**: Netflix usa Kubernetes para manejar su infraestructura

## 🎯 Tarea del Viernes {#tarea-viernes}

### **Objetivo:**

Crear y conectar microservicios usando Container Apps y App Services con variables de entorno y Key Vault.

### **Requisitos:**

#### **Arquitectura:**

- **2 servicios** en **Container Apps**
- **3 servicios** en **App Services**
- **Comunicación** entre servicios
- **Variables de entorno** para URLs y credenciales
- **Key Vault** para información sensible

#### **Funcionalidades a implementar:**

1. **Servicio A** (Container App):

   ```javascript
   // Endpoint que devuelve variable de entorno
   app.get("/config", (req, res) => {
     res.json({
       serviceUrl: process.env.SERVICE_B_URL,
       environment: process.env.ENVIRONMENT,
     });
   });
   ```

2. **Servicio B** (App Service):

   ```javascript
   // Consume el Servicio A
   const serviceAUrl = process.env.SERVICE_A_URL;
   const response = await fetch(`${serviceAUrl}/config`);
   ```

3. **Key Vault Integration:**
   ```bash
   # Variables de entorno que apuntan al Key Vault
   DATABASE_CONNECTION=@Microsoft.KeyVault(SecretUri=https://mi-keyvault.vault.azure.net/secrets/db-connection/)
   API_KEY=@Microsoft.KeyVault(SecretUri=https://mi-keyvault.vault.azure.net/secrets/api-key/)
   ```

#### **Configuración de Variables de Entorno:**

**En App Service:**

```bash
az webapp config appsettings set --name "mi-app" --resource-group "mi-rg" --settings "SERVICE_URL=https://otro-servicio.azurewebsites.net"
```

**En Container App:**

```yaml
# container-app.yaml
properties:
  configuration:
    secrets:
      - name: "db-connection"
        keyVaultUrl: "https://mi-keyvault.vault.azure.net/secrets/connection"
  template:
    containers:
      - name: "mi-container"
        env:
          - name: "DATABASE_URL"
            secretRef: "db-connection"
```

### **Entregables:**

1. **Código fuente** de los 5 microservicios
2. **Documentación** de la arquitectura
3. **Scripts de despliegue** (Azure CLI o ARM templates)
4. **Configuración** de Key Vault
5. **Pruebas** de comunicación entre servicios
