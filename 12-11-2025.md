## Volúmenes en Docker

### Problema inicial

Cuando ejecutamos `docker rm 103 -f`, todo lo que se guarde en el contenedor también se elimina. El contenido dentro del contenedor no se guarda permanentemente.

### Los 3 tipos de volúmenes

#### 1. BIND MOUNT (Mapear directorio hacia contenedor)

**¿Qué es?**

- Mapea una carpeta específica de tu máquina hacia el contenedor

**¿Para qué sirve?**

- Para que los archivos estén tanto en tu máquina como en el contenedor

**Comandos principales:**

```bash
# Ejecutar contenedor con bind mount
docker run -d -v /ruta/mi/maquina:/ruta/contenedor -p puerto_maquina:puerto_contenedor imagen

# Alternativa con --mount
docker run -d --mount source=/ruta/origen,target=/ruta/destino imagen
```

**Parámetros explicados:**

- `-d`: Ejecutar en segundo plano
- `-v`: Mapear volúmenes (ruta_mi_máquina:ruta_del_contenedor)
- `-p`: Mapear puertos (puerto_máquina:puerto_contenedor)
- `--mount`: Alternativa más explícita para montar volúmenes

**¿Cómo funciona?**
Cuando el contenedor quiere buscar archivos (como index.html), ya no irá a la ruta del contenedor sino a la ruta de tu equipo. Es como un intercambio - en lugar de buscar en la carpeta del contenedor, busca en la carpeta de tu máquina.

**Persistencia:**
Si se elimina el contenedor, los datos persisten en tu máquina.

#### 2. NAMED VOLUMES (Volúmenes con nombre)

**¿Qué es?**

- Volúmenes que Docker administra automáticamente

**¿Para qué sirve?**

- Docker se encarga de guardar y administrar los datos automáticamente

**Comandos:**

```bash
# Crear un volumen con nombre
docker volume create contenedor-t1

# Usar el volumen en un contenedor
docker run -d -v contenedor-t1:/ruta/contenedor imagen
```

**Ventaja:**
No necesitas saber dónde están los archivos físicamente - Docker los administra.

#### 3. ANONYMOUS VOLUMES (Volúmenes anónimos)

**¿Qué es?**

- Volúmenes temporales que Docker crea automáticamente

**¿Para qué sirve?**

- Para datos temporales que no necesitas administrar manualmente

**Característica:**
Se eliminan cuando se elimina el contenedor (a menos que se especifique lo contrario).

### Práctica con volúmenes

**Ejercicio propuesto:**

1. Usar base de datos MongoDB
2. Levantar contenedor usando la imagen de MongoDB
3. La información de la base de datos debe estar dentro de un directorio o volumen
4. Eliminar la imagen → los datos deben persistir

## Redes en Docker (5 tipos)

### 1. BRIDGE

**¿Qué es?**

- Permite conectar contenedores dentro de una red virtual que está dentro de Docker

**¿Para qué sirve?**

- Es como si Docker creara un espacio de intranet usando este tipo de driver

**Por defecto:**
Cuando ejecutamos `docker run -d nginx` sin especificar el tipo de driver, por defecto lo crea usando bridge.

**Comandos básicos:**

```bash
# Ver todas las redes
docker network ls

# Inspeccionar la red bridge por defecto
docker network inspect bridge
```

**Crear redes personalizadas:**

```bash
# Crear una red que use el driver bridge llamada net01
docker network create -d bridge net01

# Crear un contenedor en esa red específica
docker run -d --net=net01 --name server01 nginx

# Inspeccionar la red creada
docker network inspect net01

# Entrar al contenedor para pruebas
docker exec -it server01 bash
```

**Conectividad entre redes:**

- ¿Entre 2 bridge creados hay conectividad? **No por defecto**

**Conectar contenedores a múltiples redes:**

```bash
# Agregar otra interfaz de red (el contenedor puede estar en ambas redes)
docker network connect net02 webserver01

# Desconectar de una red específica
docker network disconnect net01 webserver01
```

### 2. HOST

**¿Qué es?**

- Comparte la misma red del host (tu máquina)

**¿Para qué sirve?**

- El contenedor usa directamente la red de tu máquina

**Comando:**

```bash
docker run -d --network host nginx
```

**Característica:**
No tiene IP propia, usará la misma IP que tiene la máquina Docker host.

### 3. OVERLAY

**¿Qué es?**

- Red para comunicar contenedores en diferentes máquinas

**¿Para qué sirve?**

- Se usa cuando queremos comunicar nodos de Docker (Docker Swarm)

**Uso:**
Para comunicar contenedores que están ejecutándose en diferentes hosts físicos.

### 4. MACVLAN

**¿Qué es?**

- Permite asignar una IP real al contenedor

**¿Para qué sirve?**

- Hacer que el contenedor aparezca como una máquina física en la red

**Ejemplo práctico:**
En una oficina/banco con red interna, cada máquina tiene una IP específica. En lugar de instalar una máquina física, puedes:

1. Crear un contenedor (ejemplo: servidor de archivos)
2. Asignarle una IP real usando MACVLAN
3. El contenedor aparecerá en la red como una máquina física más
4. Otros dispositivos en la red podrán acceder a él usando su IP real

**Resultado:**
Cuando revises la red de la oficina, verás el contenedor con una IP real y gateway, siendo visible como una máquina más, pero en realidad es solo un contenedor.

### 5. NONE

**¿Qué es?**

- Red sin conectividad

**¿Para qué sirve?**

- Para contenedores que no necesitan acceso a red

**Características:**

- No tiene IP asignada
- Es una máquina completamente aislada
- No tiene tarjeta de red o interfaz de red

## Comandos de referencia rápida

### Volúmenes:

```bash
docker volume create nombre_volumen
docker volume ls
docker volume inspect nombre_volumen
docker volume rm nombre_volumen
```

### Redes:

```bash
docker network ls
docker network create -d bridge nombre_red
docker network inspect nombre_red
docker network connect nombre_red nombre_contenedor
docker network disconnect nombre_red nombre_contenedor
docker network rm nombre_red
```

### Contenedores con redes:

```bash
docker run -d --network nombre_red --name nombre_contenedor imagen
docker exec -it nombre_contenedor bash
```
